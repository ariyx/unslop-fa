# انتخاب ایندکس برای یک endpoint پرترافیک

در PostgreSQL، اضافه کردن index همیشه به معنی سریع‌تر شدن کل سیستم نیست. index می‌تواند خواندن را سریع‌تر کند، اما هزینه نوشتن و فضای ذخیره‌سازی را هم بالا می‌برد. برای endpointی که بیشتر درخواست‌هایش بر اساس `user_id` و `created_at` فیلتر می‌شوند، بهتر است query واقعی و خروجی `EXPLAIN ANALYZE` بررسی شود.

اگر query اصلی روی دو ستون فیلتر می‌کند، یک composite index ممکن است مفید باشد، اما ترتیب ستون‌ها به الگوی query وابسته است. قبل از اضافه کردن index باید workload واقعی، نسبت read به write و اندازه جدول را بررسی کرد.
